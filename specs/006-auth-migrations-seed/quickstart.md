## Prerequisites

1. **Docker Desktop** running (if testing against local Supabase CLI).
2. **Supabase CLI** installed (`supabase --version`).
3. **Node.js 20+** and dependencies installed (`npm install`).
4. **Environment configured**: `.env.local` containing `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`.

## Verification Scenarios

### Scenario 1: Applying Database Migrations & Reset

Validate that the Supabase migration applies cleanly to a fresh database and establishes all schema objects without syntax or dependency errors.

```bash
# 1. Reset database and run all migrations + seed script
supabase db reset
```

**Expected Outcome**:
- Output confirms all migrations applied successfully.
- Enum `user_role`, table `profiles`, and indexes created without errors.
- Trigger `on_auth_user_created` attached to `auth.users`.

### Scenario 2: Verifying Seeded Demo Accounts

Confirm that demo personas are inserted with valid credentials, pre-confirmed emails, and proper profile roles.

```sql
-- Run via supabase db query, psql, or Supabase Studio SQL editor:
SELECT 
    u.id,
    u.email,
    u.email_confirmed_at IS NOT NULL AS is_confirmed,
    p.full_name,
    p.role,
    p.status
FROM auth.users u
JOIN public.profiles p ON u.id = p.id
ORDER BY p.role ASC;
```

**Expected Output**:

| id | email | is_confirmed | full_name | role | status |
| :--- | :--- | :---: | :--- | :--- | :--- |
| `<uuid-1>` | `admin@swift.local` | `true` | SWIFT Shop Admin | `admin` | `Active` |
| `<uuid-2>` | `cashier@swift.local` | `true` | SWIFT Fast-Lane Cashier | `cashier` | `Active` |

### Scenario 3: Row Level Security (RLS) Policy Verification

Validate that unauthenticated queries, self-queries, and admin queries obey security boundaries.

```sql
-- 1. Unauthenticated / Anonymous Access
SET ROLE anon;
SELECT count(*) FROM public.profiles;
-- Result: 0 rows returned (blocked by RLS)

-- 2. Staff Member Access (Simulate cashier)
SET ROLE authenticated;
SET request.jwt.claim.sub = '<uuid-2>'; -- cashier uuid
SELECT email, role FROM public.profiles;
-- Result: Returns ONLY cashier's own record (1 row)

-- 3. Admin Access (Simulate admin)
SET request.jwt.claim.sub = '<uuid-1>'; -- admin uuid
SELECT email, role FROM public.profiles;
-- Result: Returns ALL profile records (2+ rows)

-- Reset session role
RESET ROLE;
```

### Scenario 4: Live Portal Authentication Walkthrough

Validate that demo credentials allow successful sign-in on the frontend auth hub.

1. Start development server:
