## graphify

This project has a graphify knowledge graph at graphify-out/.

Rules:

- For codebase or architecture questions, when `graphify-out/graph.json` exists, first run `graphify query "<question>"` (CLI) or `query_graph` (MCP). Use `graphify path "<A>" "<B>"` / `shortest_path` for relationships and `graphify explain "<concept>"` / `get_node` for focused concepts. These return a scoped subgraph, usually much smaller than `GRAPH_REPORT.md` or raw grep output.
- If graphify-out/wiki/index.md exists, navigate it instead of reading raw files
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context
- After completing a feature branch (all tasks in `tasks.md` done) or applying schema migrations, trigger the `graphify-auto-sync` skill (`graphify . --update`) to maintain an accurate AST map without API costs.
- Before writing a new `plan.md` or major refactoring, consult `graphify query` / `graphify path` on the freshly synced graph.
